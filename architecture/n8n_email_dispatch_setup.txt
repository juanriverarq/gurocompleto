n8n - Guía de Workflow "email-dispatch" (campañas email) 

1) Resumen
- El backend Guro inicia campañas y POSTea a tu webhook de n8n con: campaign_id, subject, content, throttling_per_minute, recipients[], ignore_time_window=true.
- n8n expande recipients, rellena variables {{...}}, envía emails con throttling y reporta estado al backend.

2) Pre-requisitos en backend (validar)
- Variables en backend/.env:
  - N8N_BASE_URL=https://n8n.guro.co
  - N8N_EMAIL_DISPATCH_PATH=/webhook/4aaf6aa3-4bcd-457a-8362-168dc1360a45
  - N8N_BEARER_TOKEN=TU_TOKEN
- Limpiar cachés: php artisan config:clear && php artisan optimize:clear; reiniciar servidor.

3) Crear Workflow en n8n
- Nombre: email-dispatch
- Activar (Active): ON para usar Production Webhook.

4) Nodo 1: Webhook (Trigger)
- Method: POST
- Path: 4aaf6aa3-4bcd-457a-8362-168dc1360a45
- Production URL: https://n8n.guro.co/webhook/4aaf6aa3-4bcd-457a-8362-168dc1360a45
- Authentication:
  - Opción simple: None (acepta Authorization pero no valida).
  - Opción segura: Header Auth (Name: Authorization, Value: Bearer TU_TOKEN).
- Respond: Immediately
  - Response Code: 200
  - Response Data: JSON
  - Response Body: {"success": true, "message": "accepted", "execution_id": {{$execution.id}}}

Payload que enviará el backend (ejemplo):
{
  "campaign_id": 123,
  "broker_id": 21,
  "subject": "Asunto",
  "content": "<p>Hola {{nombre}}</p>",
  "throttling_per_minute": 30,
  "ignore_time_window": true,
  "recipients": [
    { "id": 1, "email": "a@b.com", "name": "Cliente A", "variables": { "nombre": "Ana", "numero_documento":"123" } }
  ]
}

5) Nodo 2: Function (expandir recipients + merge de variables)
- Purpose: crear 1 item por destinatario y reemplazar {{llaves}} en el HTML.
- Code (TypeScript):

// Entrada: items[0].json contiene subject, content, throttling_per_minute y recipients
const root = items[0].json;
const recipients = Array.isArray(root.recipients) ? root.recipients : [];
return recipients.map((r: any) => {
  let html = String(root.content ?? '');
  const vars = r?.variables ?? {};
  for (const [k, v] of Object.entries(vars)) {
    const re = new RegExp(`\\{\\{${k}\\}\\}`, 'g');
    html = html.replace(re, String(v ?? ''));
  }
  return {
    json: {
      campaign_id: root.campaign_id,
      subject: root.subject,
      email: r.email,
      name: r.name,
      bodyHtml: html,
      recipient_id: r.id,
      throttling: root.throttling_per_minute ?? 30
    }
  };
});

6) Nodo 3: Split In Batches
- Batch Size: 1
- Salida "Next Batch" se conectará al siguiente nodo y luego de vuelta al Split.

7) Nodo 4: Email (SMTP/SES/Mailgun)
- To: {{$json.email}}
- Subject: {{$json.subject}}
- HTML: {{$json.bodyHtml}}
- Continue On Fail: activado (para no detener la campaña por un error puntual).

8) Nodo 5: HTTP Request → callback OK al backend
- Método: POST
- URL: https://TU_BACKEND/api/webhooks/n8n/email-status
- Headers:
  - Content-Type: application/json
  - Authorization: Bearer TU_TOKEN
- Body (JSON):
{
  "campaign_id": {{$json.campaign_id}},
  "recipient": { "id": {{$json.recipient_id}}, "email": "{{$json.email}}" },
  "status": "sent",
  "timestamps": { "sent_at": "{{$now}}" }
}

9) Nodo 6: Wait (throttling)
- Fixed Duration: 2 seconds (≈ 30/min).
- Alternativa dinámica:
  - Mode: Expression
  - Seconds: {{ Math.ceil(60 / ($json.throttling || 30)) }}

10) Loop
- Conecta salida de Wait de regreso al Split In Batches → “Next Batch”.
- Conecta “No Items Left” a un fin del flujo.

11) Ruta de Error (opcional)
- En el nodo Email, configurar "Execute Once on Error" → HTTP Request (al backend) con:
- Método: POST  URL: https://TU_BACKEND/api/webhooks/n8n/email-status
- Headers: Content-Type: application/json, Authorization: Bearer TU_TOKEN
- Body (JSON):
{
  "campaign_id": {{$json.campaign_id}},
  "recipient": { "id": {{$json.recipient_id}}, "email": "{{$json.email}}" },
  "status": "failed",
  "error": "{{$json.error?.message || 'unknown error'}}"
}

12) Activar Production Webhook
- Asegúrate que el workflow está “Active”.
- Usa SIEMPRE la Production URL (no la de “Test”).

13) Prueba rápida del webhook
- Sin Auth (Webhook Auth=None):
curl -X POST 'https://n8n.guro.co/webhook/4aaf6aa3-4bcd-457a-8362-168dc1360a45' -H 'Content-Type: application/json' -d '{"ping":true}'
- Con Header Auth:
curl -X POST 'https://n8n.guro.co/webhook/4aaf6aa3-4bcd-457a-8362-168dc1360a45' -H 'Authorization: Bearer TU_TOKEN' -H 'Content-Type: application/json' -d '{"ping":true}'

14) Problemas comunes
- 404 en webhook: workflow no está Active o path distinto.
- 401 en callback al backend: faltó Authorization: Bearer TU_TOKEN en HTTP Request.
- Envío sin límite: Wait no configurado o expresión mal escrita.
- Variables {{...}} sin reemplazo: faltan en recipient.variables o contienen espacios/caracteres fuera de [a-zA-Z0-9_].

15) Seguridad mínima
- Recomendada Authentication Header en Webhook y en callback.
- El token debe coincidir con backend N8N_BEARER_TOKEN.
- Opcional: limitar origen IP en reverse proxy de n8n.
